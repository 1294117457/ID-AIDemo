# 对话持久化功能测试文档

> 测试日期：2026-05-04
> 测试范围：idagent + idbackend + idfrontend 三端联动

## 一、测试环境准备

### 1.1 启动服务顺序

```bash
# 1. 启动 idagent（端口 3001）
cd idagent && npm run dev

# 2. 启动 idbackend（端口 8080）
cd idbackend && mvn spring-boot:run
# 或直接运行 Spring Boot 主类

# 3. 启动 idfrontend（端口见 .env）
cd idfrontend && npm run dev
```

### 1.2 验证服务状态

```bash
# idagent 健康检查
curl http://localhost:3001/ai/health

# idbackend 健康检查
curl http://localhost:8080/api/user/list
# （需要登录 Token）
```

## 二、数据库验证

### 2.1 验证 SQLite 表创建

idagent 启动后，`data/agent.db` 中应自动创建以下表：

```bash
sqlite3 data/agent.db ".tables"
# 预期输出：
# ai_config  ai_conversation  ai_message
```

### 2.2 验证表结构

```bash
sqlite3 data/agent.db ".schema ai_conversation"
sqlite3 data/agent.db ".schema ai_message"
```

**预期**：

```sql
-- ai_conversation 表
CREATE TABLE ai_conversation (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     TEXT    NOT NULL,
  session_id  TEXT    NOT NULL UNIQUE,
  title       TEXT    NOT NULL DEFAULT '新对话',
  status      INTEGER NOT NULL DEFAULT 1,
  is_deleted  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT    NOT NULL,
  updated_at  TEXT    NOT NULL
);

-- ai_message 表
CREATE TABLE ai_message (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT    NOT NULL,
  role        TEXT    NOT NULL,
  content     TEXT    NOT NULL,
  msg_type    TEXT    NOT NULL DEFAULT 'message',
  extra_data  TEXT,
  created_at  TEXT    NOT NULL
);
```

## 三、API 端到端测试

### 3.1 idagent 层直接测试（无需鉴权）

**Step 1：创建会话**

```bash
curl -X POST http://localhost:3001/ai/conversation/create \
  -H "Content-Type: application/json" \
  -d '{"firstMessage":"测试对话"}'
```

**预期响应**：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "id": 1,
    "sessionId": "sess_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "title": "测试对话"
  }
}
```

记录返回的 `sessionId`。

---

**Step 2：获取会话列表**

```bash
curl -X GET "http://localhost:3001/ai/conversation/list?limit=10&offset=0"
```

**预期**：返回刚才创建的会话。

---

**Step 3：发送消息并验证消息持久化**

用 Step 1 返回的 `sessionId` 发送消息：

```bash
# 需要先模拟 x-user-id（因为会话已关联 userId）
# 直接调用 stream（测试消息写入）
# 使用任意 sessionId 发送消息
curl -X POST http://localhost:3001/ai/agent/stream \
  -F "message=你好" \
  -F "sessionId=manual_test_session"
```

验证数据库中是否写入消息：

```bash
sqlite3 data/agent.db "SELECT * FROM ai_message WHERE session_id='manual_test_session';"
```

**预期**：有至少 1 条 user 消息记录。

---

**Step 4：获取消息列表**

```bash
curl -X GET "http://localhost:3001/ai/conversation/manual_test_session/messages"
```

**预期**：返回该会话的所有消息。

---

**Step 5：更新会话标题**

```bash
curl -X PUT "http://localhost:3001/ai/conversation/manual_test_session/title" \
  -H "Content-Type: application/json" \
  -d '{"title":"我的第一个AI对话"}'
```

验证：

```bash
sqlite3 data/agent.db "SELECT title FROM ai_conversation WHERE session_id='manual_test_session';"
# 预期：我的第一个AI对话
```

---

**Step 6：删除会话**

```bash
curl -X DELETE "http://localhost:3001/ai/conversation/manual_test_session"
```

验证：

```bash
# is_deleted 应为 1
sqlite3 data/agent.db "SELECT is_deleted FROM ai_conversation WHERE session_id='manual_test_session';"
# 预期：1

# ai_message 应被清空
sqlite3 data/agent.db "SELECT COUNT(*) FROM ai_message WHERE session_id='manual_test_session';"
# 预期：0
```

## 四、前端功能测试

### 4.1 会话持久化（刷新页面后恢复）

**测试步骤**：

1. 打开 idfrontend，登录
2. 打开 AI 助手悬浮球
3. 发送一条消息，例如"你好"
4. **刷新页面**（不要点击"新对话"按钮）
5. 重新打开 AI 助手

**预期结果**：
- 之前的消息"你好"和 AI 回复都仍然显示在对话框中
- `localStorage` 中 `ai-last-session-id` 存在

**验证**：
```javascript
// 浏览器控制台
localStorage.getItem('ai-last-session-id')
// 预期：不为 null，是 sessionId 字符串
```

---

### 4.2 新建对话

**测试步骤**：

1. 在对话框中点击"新对话"按钮（右上角）
2. 输入一条新消息发送

**预期结果**：
- 对话框清空
- 发送后数据库中新增一条 `ai_conversation` 记录（`user_id` 为当前用户）
- 之前的旧对话仍然保存在数据库中

**验证**：

```bash

sqlite3 data/agent.db "SELECT COUNT(*) FROM ai_conversation WHERE is_deleted=0;"
```

### 5.1 验证 Checkpoint 创建

```bash
sqlite3 data/checkpoints.db "SELECT thread_id, created_at, updated_at FROM checkpoints LIMIT 5;"
```

**预期**：有记录，`thread_id` 为 sessionId 格式。

### 5.2 验证状态恢复

1. 创建一个对话并完成至少一轮交互（包含 AI 回复）
2. 关闭 idagent 服务
3. 重新启动 idagent
4. 在前端选择同一会话继续对话

**预期结果**：
- AI 能够正确理解上下文（之前对话的内容）
- 不会丢失之前设置的 `intent`、`documentText` 等状态

## 六、异常场景测试

**预期结果**：

**预期结果**：

- 消息可能只部分写入（用户消息已存，AI 回复未存）

**测试步骤**：
用相同 `sessionId` 在不同浏览器/标签页同时发送消息

**预期结果**：
- LangGraph Checkpoint 机制保证状态一致
- 不会出现数据混乱

## 八、已知问题与限制

1. **多实例部署**：idagent 目前为单实例，SQLite 不支持跨进程并发写入。未来扩展需切换 PostgreSQL。
2. **用户隔离**：依赖 idbackend 正确注入 `x-user-id`，未登录用户无法使用会话持久化（会退化为纯内存模式）。
3. **消息与 Checkpoint 双写**：AI 回复在 SSE 结束后写入 `ai_message`，若中途断开可能导致消息未完全持久化（但 Checkpoint 中已有记录）。
