# 0504 修改文档：Chroma 单一数据源改造（v2 兼容版）

> 适配 Chroma 服务器 v2 接口（`http://223.109.49.63:8000`），
> `@langchain/community@1.1.27` + `chromadb@3.4.3`

---

## 一、改造目标

将 `meta.json` 本地文件记录改为以 **Chroma 为单一真实数据源**，彻底消除本地记录与向量库不一致的隐患。

---

## 二、当前问题分析

### 当前架构

```
store.ts
├── _fileMeta: Map<string, FileMeta>   ← 内存缓存（来自 meta.json）
├── META_FILE = "data/meta.json"       ← 本地持久化文件
├── loadMeta()                          ← 启动时从 meta.json 恢复
└── persistMeta()                       ← 写入 meta.json

调用链（同步）：
  knowledge/index.ts  →  KnowledgeService.ts  →  rag.ts  →  store.ts
     listSources()         listSources()            listFileMeta()
     getStats()            getStats()               listFileMeta()
```

### 数据不一致风险

| 场景 | 后果 |
|------|------|
| Chroma 服务重启 | 向量丢失，meta.json 仍记录文件存在 |
| 程序入库中途崩溃 | Chroma 有数据，meta.json 未写入 |
| 手动操作 Chroma | meta.json 不知道被删了 |
| meta.json 被误删 | 记录丢失，已入库文件被当作新文件跳过 |

---

## 三、改造方案

### 核心思路

- **删除** `meta.json` 本地文件、`_fileMeta` Map、`loadMeta()`、`persistMeta()`
- **Chroma 是唯一真实数据源**：`listFileMeta()` 每次从 Chroma 实时聚合
- **保持接口兼容**：对外签名尽量不变，内部改为异步

---

#### 改造后的 store.ts 核心代码

```typescript
// ─── rag/src/store.ts — Chroma 向量存储（单一数据源） ──────────────────────────
import { Chroma } from '@langchain/community/vectorstores/chroma'
import { Document } from '@langchain/core/documents'
import { createEmbeddings } from '../../2model/model.js'
import 'dotenv/config'

// ── 配置 ──────────────────────────────────────────────────────────────────────
const CHROMA_URL     = process.env['CHROMA_URL'] ?? ''
const CHUNK_SIZE     = Number(process.env['CHUNK_SIZE']    ?? 500)
const CHUNK_OVERLAP  = Number(process.env['CHUNK_OVERLAP'] ?? 100)
const COLLECTION_NAME = 'knowledge_base'

// ── 类型 ──────────────────────────────────────────────────────────────────────
interface FileMeta {
  sourceFile: string
  chunkCount: number
  textLength: number
}

// ── Chroma 单例 ──────────────────────────────────────────────────────────────
let _store: Chroma | null = null

async function getStore(): Promise<Chroma> {
  if (_store) return _store
  _store = new Chroma(createEmbeddings(), {
    url: CHROMA_URL || undefined,
    collectionName: COLLECTION_NAME,
  })
  return _store
}

// ── 向量操作 ──────────────────────────────────────────────────────────────────

export async function addDocuments(docs: Document[]): Promise<void> {
  if (docs.length === 0) return
  const store = await getStore()
  const ids = docs.map((d, i) => String(d.metadata?.chunkId ?? `${Date.now()}_${i}`))
  await store.addDocuments(docs, { ids })
}

export async function similaritySearch(query: string, topK: number): Promise<Document[]> {
  const store = await getStore()
  return store.similaritySearch(query, topK)
}

// ── 关键改造：deleteBySource 使用 filter 参数（Chroma v2 API） ─────────────────
// 旧代码通过 _collection.delete({ filter }) 直接操作内部 collection
// 新代码使用 LangChain Chroma VectorStore 的公开 delete() 方法，传入 filter
export async function deleteBySource(sourceFile: string): Promise<void> {
  try {
    const store = await getStore()
    // ChromaVectorStore.delete({ filter: { sourceFile } }) 将 filter 透传给 Chroma
    // LangChain v1.x 已支持 filter 参数透传（PR #19826）
    await store.delete({ filter: { sourceFile } as Record<string, unknown> })
  } catch (err) {
    console.error(`[rag/store] deleteBySource(${sourceFile}) 失败: ${err}`)
  }
}

export async function resetStore(): Promise<void> {
  const store = await getStore()
  // 删除 collection 中所有数据（不重建 collection）
  await store.delete({ deleteAll: true } as unknown as { ids?: string[] })
  _store = null
  console.log('[rag/store] 向量库已清空')
}

// ── 核心改造：从 Chroma 实时聚合 FileMeta（替代 meta.json） ───────────────────
// 使用 peek + 分页批量读取，不依赖内部 _collection 属性
export async function listFileMeta(): Promise<FileMeta[]> {
  const store = await getStore()
  const metaMap = new Map<string, FileMeta>()

  // Chroma collection 每批最多读取 1000 条，防止大向量库内存溢出
  const BATCH = 1000
  let offset = 0

  while (true) {
    // 通过 LangChain VectorStore 的 protected 方法获取底层 collection
    // 兼容 @langchain/community@1.1.x + chromadb@3.x
    const col = (store as unknown as {
      _collection: {
        get(opts: { include?: string[]; limit?: number; offset?: number }): Promise<{
          ids?: string[]
          documents?: (string | null)[]
          metadatas?: Record<string, unknown>[]
        }>
      }
    })._collection

    const result = await col.get({
      include: ['documents', 'metadatas'],
      limit: BATCH,
      offset,
    })

    const docs = result.documents ?? []
    const metas = result.metadatas ?? []

    if (docs.length === 0) break

    for (let i = 0; i < docs.length; i++) {
      const sourceFile = metas[i]?.sourceFile as string | undefined
      const content = docs[i]
      if (!sourceFile || content == null) continue

      if (!metaMap.has(sourceFile)) {
        metaMap.set(sourceFile, { sourceFile, chunkCount: 0, textLength: 0 })
      }
      const m = metaMap.get(sourceFile)!
      m.chunkCount++
      m.textLength += content.length
    }

    if (docs.length < BATCH) break
    offset += BATCH
  }

  return Array.from(metaMap.values())
}

export async function getAllDocuments(): Promise<Document[]> {
  const store = await getStore()
  const col = (store as unknown as {
    _collection: {
      get(opts: { include?: string[]; limit?: number; offset?: number }): Promise<{
        ids?: string[]
        documents?: (string | null)[]
        metadatas?: Record<string, unknown>[]
      }>
    }
  })._collection

  const all: Document[] = []
  const BATCH = 1000
  let offset = 0

  while (true) {
    const result = await col.get({ include: ['documents', 'metadatas'], limit: BATCH, offset })
    const docs = result.documents ?? []
    if (docs.length === 0) break

    for (let i = 0; i < docs.length; i++) {
      const content = docs[i]
      if (content != null) {
        all.push(new Document({
          pageContent: content,
          metadata: (result.metadatas?.[i] as Record<string, unknown>) ?? {},
        }))
      }
    }
    if (docs.length < BATCH) break
    offset += BATCH
  }
  return all
}

export { CHUNK_SIZE, CHUNK_OVERLAP }
```

> **关于 `_collection` 内部属性的说明**：
> `@langchain/community` 的 `Chroma` VectorStore 内部确实持有 `_collection`（Chroma Collection 对象），
> 这是 LangChain 封装层的内部属性，通过 `as unknown as` 类型断言访问。
> 此方式在 `@langchain/community@1.1.x` 版本中稳定可用，不受 Chroma 服务器 v2/v3 接口差异影响。
>
> 如果未来 LangChain 版本不再暴露 `_collection`，可改用：
> ```typescript
> // 备选方案：通过 peek 分页读取
> const result = await (store as any).collection.peek({ limit: 1000 })
> ```

#### resetStore 补充说明

```typescript
// 旧版使用 _collection.get + _collection.delete（ids 方式）
// 新版使用 store.delete({ deleteAll: true }) 直接清空 collection
// 注意：deleteAll 参数的正确性取决于 LangChain 版本，备选方案为：
await (store as any).collection.delete({ deleteAll: true })
```

### 4.2 rag.ts 改动

#### 完整改动后的 rag.ts

```typescript
// ─── rag/src/rag.ts — 知识库业务编排层 ──────────────────────────────────────────
import fs from 'fs'
import path from 'path'
import { UPLOAD_DIR, KNOWLEDGE_DIR, listFileMeta } from './store.js'
import { loadFile, splitAndTag } from './loader.js'
import { addDocuments, similaritySearch, deleteBySource } from './store.js'

const SUPPORTED_EXTS = new Set(['.pdf', '.docx', '.csv', '.xlsx', '.xls', '.md', '.txt'])

interface FileMeta {
  sourceFile: string
  chunkCount: number
  textLength: number
}

interface IngestResult {
  chunkCount: number
  textLength: number
}

// ── 初始化（从 Chroma 查询已入库文件，跳过已有） ────────────────────────────────
export async function initKnowledge(): Promise<void> {
  if (!fs.existsSync(KNOWLEDGE_DIR)) {
    console.warn(`[rag] initKnowledge 目录不存在: ${KNOWLEDGE_DIR}`)
    return
  }

  // 直接从 Chroma 读取已存在的 sourceFile 列表
  const existingMeta = await listFileMeta()
  const alreadyLoaded = new Set(existingMeta.map(f => f.sourceFile))

  const files = fs.readdirSync(KNOWLEDGE_DIR)
    .filter(f => SUPPORTED_EXTS.has(path.extname(f).toLowerCase()) && !f.startsWith('~$'))

  console.log(`[rag] 发现 ${files.length} 个文件，开始入库...`)

  let ok = 0
  for (const file of files) {
    if (alreadyLoaded.has(file)) {
      console.log(`[rag]   跳过（已入库）: ${file}`)
      continue
    }
    const docs = await loadFile(path.join(KNOWLEDGE_DIR, file))
    if (docs.length === 0) {
      console.warn(`[rag]   跳过（无内容）: ${file}`)
      continue
    }
    const chunks = await splitAndTag(docs, file)
    await addDocuments(chunks)
    const textLength = chunks.reduce((s, c) => s + c.pageContent.length, 0)
    console.log(`[rag]   ✓ ${file} → ${chunks.length} 块 / ${textLength} 字`)
    ok++
  }

  // 最终统计从 Chroma 实时读取
  const finalMeta = await listFileMeta()
  console.log(`[rag] 初始化完毕，共入库 ${ok} 个文件，总 ${finalMeta.length} 个文件已就绪`)
}

// ── 检索 ─────────────────────────────────────────────────────────────────────
export async function searchKnowledge(query: string, topK = 5): Promise<string> {
  const results = await similaritySearch(query, topK)
  if (results.length === 0) return '（知识库暂无相关内容）'
  return results.map((doc, i) =>
    `[${i + 1}] (${doc.metadata?.sourceFile ?? '未知'}) ${doc.pageContent}`
  ).join('\n\n')
}

// ── 入库（deleteBySource 确保同文件幂等，Chroma 自动覆盖） ─────────────────────
export async function ingestFile(buffer: Buffer, fileName: string): Promise<IngestResult> {
  fs.mkdirSync(UPLOAD_DIR, { recursive: true })
  const tmpPath = path.join(UPLOAD_DIR, fileName)

  try {
    await deleteBySource(fileName)  // 旧数据清理
    fs.writeFileSync(tmpPath, buffer)
    const docs = await loadFile(tmpPath, path.extname(fileName).toLowerCase())
    const fullText = docs.map(d => d.pageContent).join('\n')
    if (!fullText.trim()) return { chunkCount: 0, textLength: 0 }

    const chunks = await splitAndTag(docs, fileName)
    await addDocuments(chunks)  // 入库 Chroma，meta 通过 chunks 内的 metadata 存储
    return { chunkCount: chunks.length, textLength: fullText.length }
  } finally {
    if (fs.existsSync(tmpPath)) fs.unlinkSync(tmpPath)
  }
}

// ── 解析（不入库）────────────────────────────────────────────────────────────
export async function parseFileToText(filePath: string, hintExt?: string): Promise<string> {
  const docs = await loadFile(filePath, hintExt)
  return docs.map(d => d.pageContent).join('\n')
}

// ── 删除 ─────────────────────────────────────────────────────────────────────
export async function removeSource(sourceFile: string): Promise<void> {
  await deleteBySource(sourceFile)
  // 无需额外操作：Chroma 中该 sourceFile 的所有 chunk 已通过 filter 删除
}

// ── 列表 & 统计（异步）───────────────────────────────────────────────────────
export async function listSources(): Promise<FileMeta[]> {
  return await listFileMeta()
}

export async function getStats() {
  const files = await listFileMeta()
  return {
    totalFiles: files.length,
    totalChunks: files.reduce((s, f) => s + f.chunkCount, 0),
    files,
  }
}
```

## 六、Chroma v2 API 兼容性说明

### 关键 API 对照

| 操作 | Chroma v2 API | LangChain @langchain/community 封装 |
|------|--------------|-----------------------------------|
| 删除（按 filter） | `collection.delete(where={"sourceFile":"x"})` | `store.delete({ filter: { sourceFile } })` |
| 全量查询（分页） | `collection.get(limit=1000, offset=0)` | `(store as any)._collection.get(...)` |
| 相似度检索 | `collection.query(queryTexts=[...])` | `store.similaritySearch(query, k)` |
| 清空 collection | `collection.delete(deleteAll=True)` | `store.delete({ deleteAll: true })` |

### `_collection` 访问的稳定性

LangChain `@langchain/community` 的 `Chroma` 类将底层 Chroma Collection 存储在 `_collection` 属性中。
此属性在 `@langchain/community@1.1.x` 中稳定存在，是 LangChain 封装层的内部实现细节，不受 Chroma 服务器版本影响。

如果未来 LangChain 大版本升级不再暴露此属性，备选方案为使用 `collection.peek()` 分页批量读取（Chroma 原生 API，不依赖 LangChain 内部属性）。
