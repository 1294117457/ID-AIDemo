# 请求提示统一方案分析

> 生成时间：2026-05-06
> 目标：将所有前端请求提示统一由后端返回的 `msg` 字段显示

---

## 一、现状分析

### 1.1 统一响应格式

后端所有接口统一返回 `ResultVo<T>`：

```java
public class ResultVo<T> {
    private Integer code;   // 200=成功，其他为错误
    private String msg;     // 提示信息
    private T data;         // 数据
}
```

#### ResultVo 标准方法

| 方法 | code | 用途 |
|------|------|------|
| `success(msg, data)` | 200 | 成功（带msg） |
| `success(msg)` | 200 | 成功（无data） |
| `error(msg)` | 500 | 通用错误 |
| `error(code, msg)` | 自定义 | 指定状态码错误 |
| `loginError(msg)` | 401 | 登录失败 |
| `captchaError(msg)` | 400 | 验证码错误 |
| `forbidden(msg)` | 403 | 禁止访问 |
| `loginSuccess(msg, data)` | 201 | 登录成功（特殊） |

## 二、前端现状

### 2.1 idfrontend（学生端）

#### http.ts 当前逻辑

```
请求成功 (code=200)：
  - GET 请求：不弹任何提示
  - 非GET请求：若 res.msg !== '成功'，ElMessage.success(res.msg)

请求失败 (code≠200)：
  - code=401：清除token，跳转登录，ElMessage.error('登录已过期，请重新登录')
  - 其他错误码：ElMessage.error(res.msg || '请求失败')

网络异常：
  ElMessage.error((error.response?.data)?.msg || '网络异常，请稍后重试')
```

#### 存在的问题

| # | 问题 | 严重程度 |
|---|------|---------|
| 1 | 成功时只有非GET且msg≠'成功'才弹success提示，很多操作静默成功无提示 | **中** |
| 2 | GET请求（查询）即使后端返回msg也不展示，不直观 | **低** |
| 3 | `msg === '成功'` 时静默，可能丢失有意义的自定义成功消息 | **低** |
| 4 | 路由守卫中有一处 `ElMessage.warning('请先登录')` 硬编码（router/index.ts:28） | **低** |

### 3.2 后端需修改的问题

#### 问题1：AICHatService 中直接返回 ResultVo（不应在Service层返回）

| 文件 | 方法 | 问题 |
|------|------|------|
| `AICHatService.java` | `forwardConversationList` | 直接返回 `ResultVo`，但调用方已通过 `parseAgentResponse` 二次包装 |
| `AICHatService.java` | 其他 forward* 方法 | 同上，导致 msg 被覆盖为"成功" |

**原因**：`forwardConversationList` 等方法调用 `parseAgentResponse(raw)` 再次将 agent 的 `code/msg` 包装为新的 `ResultVo`，成功时 msg 固定为 "成功"。

**修改方案**：这些方法应直接返回 agent 的原始响应字符串，由 Controller 层包装，或统一修改 `parseAgentResponse` 的成功 msg 为 agent 原始 msg。

#### 问题2：msg 过于通用（建议性改进，非必须）

| 文件 | 位置 | 当前msg | 建议 |
|------|------|--------|------|
| `RoleController` | 各查询接口 | "查询成功" | 可保留（查询操作不弹提示） |
| `PermissionController` | 各查询接口 | "查询成功" | 可保留 |
| `UserRoleController` | 各接口 | "查询成功"/"添加成功" | 良好 |
| `AttributeController` | 各接口 | "查询成功" | 可保留 |
| `AICHatController.chat()` | 成功时 | "成功" | 建议改为具体描述 |
| `ChatController.chat()` | 成功时 | "成功" | 建议改为具体描述 |
| `InternalAgentController` | 错误时 | "forbidden" | **需改为中文** |

#### 问题3：AICHatService 中 parseAgentResponse 成功时 msg 固定为"成功"

| 文件行 | 代码 | 问题 |
|--------|------|------|
| `AICHatService.java:442` | `ResultVo.success("成功", json.get("data"))` | agent返回的msg被丢弃，固定显示"成功" |

**修改方案**：改为 `ResultVo.success(json.optString("msg", "操作成功"), json.get("data"))`，保留 agent 返回的 msg。

## 四、建议修改方案

### 4.1 前端修改（统一提示逻辑）

#### idfrontend/src/common/utils/http.ts

```typescript
apiClient.interceptors.response.use(
  (response) => {
    const res = response.data

    // code=401：token过期
    if (res.code === 401) {
      clearTokensAndRedirect()
      return Promise.reject(res)
    }

    // code≠200：业务错误
    if (res.code !== 200) {
      ElMessage.error(res.msg || '请求失败')
      return Promise.reject(res)
    }

    // code=200：成功提示（展示后端msg）
    const method = response.config.method?.toLowerCase()
    if (method !== 'get') {
      // 非GET请求：展示后端返回的msg（无论是否为"成功"）
      if (res.msg) {
        ElMessage.success(res.msg)
      }
    }

    return res
  },
  // ... error handler 不变
)
```

**关键变化**：去掉 `&& res.msg !== '成功'` 条件，改为只要非GET请求就展示后端msg。

#### idfrontend/src/router/index.ts

移除 `ElMessage.warning('请先登录')`，由后端返回401后前端自动提示。

#### idfrontend-admin/src/common/utils/http.ts

同上，修改逻辑保持一致。

#### 各 Vue 组件中的 ElMessage 调用

**原则**：HTTP请求相关的提示应全部移除，由 http.ts 统一处理。组件内部保留的 ElMessage 仅用于：

- UI交互反馈（如表单校验失败、输入错误等不经过HTTP的场景）
- 特殊业务逻辑的本地提示

建议逐文件检查并移除调用后端接口后自行显示的 ElMessage。

### 4.2 后端修改（确保msg规范）

#### 必须修改

| # | 文件 | 修改内容 |
|---|------|---------|
| 1 | `AICHatService.java:442` | `success("成功", ...)` → `success(json.optString("msg", "操作成功"), ...)` |
| 2 | `InternalAgentController.java:41` | `"forbidden"` → `"禁止访问"` |

#### 建议修改（可选，msg更友好）

| # | 文件 | 当前 | 建议 |
|---|------|------|------|
| 1 | `AICHatController.chat()` | `ResultVo.success("成功", data)` | `ResultVo.success("AI回复已生成", data)` |
| 2 | `ChatController.chat()` | `ResultVo.success("成功", reply)` | `ResultVo.success("AI回复已生成", reply)` |

### 4.3 不适用此方案的场景

| 场景 | 说明 |
|------|------|
| SSE 流式接口 | `AIApplyController.stream()`、`AICHatController.stream()` 等返回 `SseEmitter`，前端通过 SSE 数据中的字段自行处理提示 |
| 文件下载 | `FileController.downloadFile()` 返回 `void`，由前端处理 |

## 五、修改优先级

| 优先级 | 修改项 | 范围 |
|--------|--------|------|
| **P0 必须** | http.ts 拦截器逻辑统一（去掉 `&& res.msg !== '成功'`） | 2个前端，各1处 |
| **P0 必须** | AICHatService parseAgentResponse 保留agent原始msg | 后端1处 |
| **P0 必须** | InternalAgentController msg改为中文 | 后端1处 |
| **P1 推荐** | 移除各Vue组件中调用后端接口后的ElMessage | 两个前端，30+个文件 |
| **P1 推荐** | idfrontend router/index.ts 移除硬编码 ElMessage | 前端1处 |
| **P2 可选** | Chat/AICHatController 成功msg改为具体描述 | 后端2处 |

## 六、总结

- **后端**：整体格式规范，`ResultVo` 统一，所有接口均有 msg
- **前端**：http.ts 拦截器已能处理后端msg，但有过滤条件导致部分提示不显示
- **主要工作**：前端去掉过滤条件 + 后端确保msg有意义 + 清理各组件中的冗余 ElMessage
