# 2. 模型网关 + 多租户模型配置

> 本文档将 **设计1（模型网关 Router + Adapter）** 和 **设计2（多租户模型配置）** 合并实现，一次改动同时满足两个设计目标。

---

## 一、现状分析

### 1.1 当前数据库结构

```sql
-- ai_config（全局单配置，无 tenant_id）
config_key | config_value
-----------|-------------------------------
api_key    | sk-xxx
base_url   | https://dashscope.aliyuncs.com/...
chat_model | qwen3-max
...

-- ai_conversation（只有 user_id，无 tenant_id）
user_id | session_id | ...
--------|------------|-----
```

### 1.2 当前配置读取链路

```
config.ts getApiKey()
  → loadAll() 读取 ai_config 表
  → 60s TTL 缓存
  → 无 tenant 维度
```

### 1.3 当前模型工厂链路

```
createChatModel(temperature)
  → new ChatOpenAI({ ... })  // 写死厂商
  → getApiKey() / getBaseUrl() / getChatModel()  // 全局配置
  → 无场景区分
  → 无多厂商支持
```

### 1.4 当前问题汇总

| 问题 | 现状 | 影响 |
|------|------|------|
| 全局单配置 | `ai_config` 只有 system 级 | 多校使用时配置互相覆盖 |
| 无 tenant_id | `ai_conversation`/`ai_message` 无隔离字段 | 数据泄露风险 |
| 硬编码厂商 | `new ChatOpenAI()` 写死 | 无法切换到 OpenAI/DeepSeek |
| 无版本化 | 配置改完即覆盖，无快照 | 无法回滚 |
| 无热切换 | 依赖 60s TTL，被动过期 | 配置变更延迟生效 |
| JWT 无 tenantId | 后端 JWT payload 无 tenantId | 无法按租户选配置 |

## 二、目标架构

### 2.1 整体数据流

```
HTTP 请求（带 Authorization: Bearer <JWT>）
         │
         ▼
requireAuth 中间件
  └─ verifyJWT(token) 解码 JWT
       └─ JWT payload 中取出 tenantId + userId
            │
            ▼
requestContext.run({ tenantId, userId, token }, () => next())
  └─ AsyncLocalStorage 全局存储，后续异步链都能取到
         │
         ▼
AgentService / Router / 任意服务层
  └─ getCurrentTenantId() → 拿到当前请求的 tenantId
       │
       ▼
Router.getModelConfig(tenantId, scenario)
  └─ 先查 ai_tenant_config（租户专属）
  └─ 无则回退 ai_config（system 级兜底）
  └─ 命中 version 则记录快照
       │
       ▼
AdapterFactory.create(vendor, config)
  └─ QwenAdapter / OpenAIAdapter / DeepSeekAdapter
       │
       ▼
LangChain 模型实例（带缓存）
```

## 三、数据库迁移

### 3.1 新增表 SQL

> 直接在 `config.ts` 的 `initDb()` 中追加即可（SQLite `CREATE TABLE IF NOT EXISTS` 天然幂等）。

```sql
-- ── 租户信息表 ──────────────────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS ai_tenant (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id   TEXT    NOT NULL UNIQUE,
  name        TEXT    NOT NULL,
  is_active   INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_tenant_id ON ai_tenant(tenant_id);

-- ── 租户级配置（覆盖 ai_config 的默认值）─────────────────────────────────────
CREATE TABLE IF NOT EXISTS ai_tenant_config (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id    TEXT    NOT NULL,
  config_key   TEXT    NOT NULL,
  config_value TEXT    NOT NULL,
  updated_at   INTEGER NOT NULL DEFAULT (unixepoch()),
  UNIQUE(tenant_id, config_key)
);
CREATE INDEX IF NOT EXISTS idx_tc_tenant ON ai_tenant_config(tenant_id);

-- ── 配置版本快照（支持回滚）─────────────────────────────────────────────────
CREATE TABLE IF NOT EXISTS ai_config_version (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id    TEXT    NOT NULL DEFAULT 'system',
  config_key   TEXT    NOT NULL,
  config_value TEXT    NOT NULL,
  version      INTEGER NOT NULL,
  created_at   TEXT    NOT NULL,
  UNIQUE(tenant_id, config_key, version)
);
CREATE INDEX IF NOT EXISTS idx_cv_tenant ON ai_config_version(tenant_id);
```

### 3.2 现有表改造

> 已有表 `ai_conversation` 和 `ai_message` 加 `tenant_id` 列。SQLite `ADD COLUMN` 配合 `IF NOT EXISTS` 幂等安全。

```sql
ALTER TABLE ai_message    ADD COLUMN tenant_id TEXT NOT NULL DEFAULT 'default';
```

```typescript
  userId: number
  tenantId: string            // ← 新增：租户标识（来自后端 JWT）

  exp: number
  iat: number
}

// ── 验证函数中的解码逻辑（改动）────────────────────────────────────────────────

export function verifyJWT(token: string): JWTPayload {
  try {
    const decoded = jwt.verify(token, JWT_SECRET) as jwt.JwtPayload

    const payload: JWTPayload = {
      tokenType: (decoded['tokenType'] as string) as 'access' | 'refresh',
      userId:    decoded['userId'] as number,
      tenantId:  (decoded['tenantId'] as string) || 'default',   // ← 新增，带默认值兜底
      sub:       decoded['sub'] as string,
      exp:       decoded['exp'] as number,
      iat:       decoded['iat'] as number,
    }
    // ... 其余验证逻辑不变 ...
  }
  // ...
}
```

#### 改动 2：新增租户配置读取函数（在 config.ts 末尾添加）

```typescript
// ── 多租户配置读取 ──────────────────────────────────────────────────────────
// 优先级：ai_tenant_config（租户级） > ai_config（system 级兜底）

/**
 * 获取指定租户的某项配置值
 * 先查租户专属配置，无则回退 system 级
 */
export function getTenantConfig(tenantId: string, key: string): string | null {
  const db = getDb()
  // 先查租户专属配置
  const row = db.prepare(
    `SELECT config_value FROM ai_tenant_config WHERE tenant_id = ? AND config_key = ?`
  ).get(tenantId, key) as { config_value: string } | undefined
  if (row) return row.config_value
  // 回退到 system 级
  return db.prepare(
    `SELECT config_value FROM ai_config WHERE config_key = ?`
  ).get(key) as { config_value: string } | undefined
    ?? null
}

/**
 * 获取指定租户的所有配置（合并后结果）
 * 租户级覆盖 system 级，未覆盖的字段用 system 级值
 */
export function getAllConfigsForTenant(tenantId: string): Record<string, string> {
  const db = getDb()
  // system 级（兜底）
  const systemRows = db.prepare(
    `SELECT config_key, config_value FROM ai_config`
  ).all() as { config_key: string; config_value: string }[]
  const result: Record<string, string> = {}
  for (const r of systemRows) result[r.config_key] = r.config_value
  // 租户级覆盖
  const tenantRows = db.prepare(
    `SELECT config_key, config_value FROM ai_tenant_config WHERE tenant_id = ?`
  ).all(tenantId) as { config_key: string; config_value: string }[]
  for (const r of tenantRows) result[r.config_key] = r.config_value
  return result
}

// ── 配置版本快照 ──────────────────────────────────────────────────────────────

/**
 * 写入一条配置版本快照
 * 每次 updateConfig 时自动调用，保存变更前的值
 */
export function snapshotConfigVersion(
  tenantId: string,
  key: string,
  oldValue: string
): void {
  const db = getDb()
  // 获取当前最大版本号
  const row = db.prepare(
    `SELECT MAX(version) AS max_ver FROM ai_config_version WHERE tenant_id = ? AND config_key = ?`
  ).get(tenantId, key) as { max_ver: number | null }
  const nextVersion = (row?.max_ver ?? 0) + 1
  db.prepare(
    `INSERT INTO ai_config_version (tenant_id, config_key, config_value, version, created_at)
     VALUES (?, ?, ?, ?, datetime('now'))`
  ).run(tenantId, key, oldValue, nextVersion)
}

/**
 * 获取指定租户某配置的版本历史
 */
export function getConfigVersions(tenantId: string, key: string): Array<{ version: number; value: string; created_at: string }> {
  const db = getDb()
  return db.prepare(
    `SELECT version, config_value AS value, created_at
     FROM ai_config_version
     WHERE tenant_id = ? AND config_key = ?
     ORDER BY version DESC`
  ).all(tenantId, key) as Array<{ version: number; value: string; created_at: string }>
}

/**
 * 回滚到指定版本
 */
export function rollbackConfig(tenantId: string, key: string, version: number): boolean {
  const db = getDb()
  const row = db.prepare(
    `SELECT config_value FROM ai_config_version
     WHERE tenant_id = ? AND config_key = ? AND version = ?`
  ).get(tenantId, key, version) as { config_value: string } | undefined
  if (!row) return false
  // 写回租户配置（或 system 配置）
  const effectiveTenantId = tenantId === 'default' ? 'system' : tenantId
  const oldValue = getTenantConfig(effectiveTenantId, key)
  snapshotConfigVersion(effectiveTenantId, key, oldValue ?? '')
  upsertTenantOrSystemConfig(effectiveTenantId, key, row.config_value)
  return true
}

// 内部：upsert 到租户配置或 system 配置
function upsertTenantOrSystemConfig(tenantId: string, key: string, value: string): void {
  const db = getDb()
  if (tenantId === 'system') {
    db.prepare(
      `INSERT INTO ai_config (config_key, config_value, updated_at)
       VALUES (?, ?, unixepoch())
       ON CONFLICT(config_key) DO UPDATE SET config_value = excluded.config_value, updated_at = unixepoch()`
    ).run(key, value)
  } else {
    db.prepare(
      `INSERT INTO ai_tenant_config (tenant_id, config_key, config_value, updated_at)
       VALUES (?, ?, ?, unixepoch())
       ON CONFLICT(tenant_id, config_key) DO UPDATE SET config_value = excluded.config_value, updated_at = unixepoch()`
    ).run(tenantId, key, value)
  }
}

// ── 配置变更通知（热切换）─────────────────────────────────────────────────────

type ConfigChangeListener = (tenantId: string, key: string, newValue: string) => void
const _listeners: ConfigChangeListener[] = []

export function onConfigChange(listener: ConfigChangeListener): () => void {
  _listeners.push(listener)
  return () => {
    const idx = _listeners.indexOf(listener)
    if (idx !== -1) _listeners.splice(idx, 1)
  }
}

function notifyConfigChange(tenantId: string, key: string, value: string): void {
  for (const l of _listeners) {
    try { l(tenantId, key, value) } catch (_) {}
  }
}
```

#### 改动 3：修改 updateConfig 函数支持版本快照

将原有的 `updateConfig` 函数替换为：

```typescript
export interface ConfigUpdate {
  tenantId?:           string          // ← 新增：指定要修改哪个租户的配置（默认 'default'）
  systemRole?:         string
  apiKey?:             string
  baseUrl?:            string
  chatModel?:          string
  embeddingModel?:      string
  contextMaxMessages?:  number
  vendor?:              string          // ← 新增
  embeddingVendor?:     string          // ← 新增
  snapshot?:           boolean         // ← 新增：是否记录版本快照（默认 true）
}

export function updateConfig(update: ConfigUpdate): void {
  const db = getDb()
  const tenantId = update.tenantId ?? 'default'
  const doSnapshot = update.snapshot !== false

  // 如果是 system 级配置变更，先快照
  if (doSnapshot && tenantId === 'default') {
    const allKeys = ['api_key', 'base_url', 'chat_model', 'embedding_model', 'vendor', 'embedding_vendor', 'system_role']
    for (const k of allKeys) {
      const oldVal = (loadAll() as Record<string, string>)[k]
      if (oldVal != null) snapshotConfigVersion('system', k, oldVal)
    }
  }

  // upsert 到 ai_tenant_config（租户级）
  const upsertTenantConfig = db.prepare(
    `INSERT INTO ai_tenant_config (tenant_id, config_key, config_value, updated_at)
     VALUES (?, ?, ?, unixepoch())
     ON CONFLICT(tenant_id, config_key) DO UPDATE
     SET config_value = excluded.config_value, updated_at = unixepoch()`
  )
  const upsertSystemConfig = db.prepare(
    `INSERT INTO ai_config (config_key, config_value, updated_at)
     VALUES (?, ?, unixepoch())
     ON CONFLICT(config_key) DO UPDATE
     SET config_value = excluded.config_value, updated_at = unixepoch()`
  )

  const upsertMany = db.transaction((entries: [string, string, 'tenant' | 'system'][]) => {
    for (const [k, v, scope] of entries) {
      if (scope === 'tenant') upsertTenantConfig.run(tenantId, k, v)
      else upsertSystemConfig.run(k, v)
    }
  })

  const entries: [string, string, 'tenant' | 'system'][] = []
  const scope = tenantId === 'default' ? 'system' : 'tenant'

  if (update.systemRole    != null) entries.push(['system_role',         update.systemRole, scope])
  if (update.apiKey        != null && update.apiKey.trim() !== '')
                                       entries.push(['api_key',             update.apiKey.trim(), scope])
  if (update.baseUrl       != null) entries.push(['base_url',            update.baseUrl, scope])
  if (update.chatModel     != null) entries.push(['chat_model',          update.chatModel, scope])
  if (update.embeddingModel!= null) entries.push(['embedding_model',    update.embeddingModel, scope])
  if (update.contextMaxMessages != null)
                                       entries.push(['context_max_messages', String(update.contextMaxMessages), scope])
  if (update.vendor        != null) entries.push(['vendor',              update.vendor, scope])
  if (update.embeddingVendor!= null) entries.push(['embedding_vendor',  update.embeddingVendor, scope])

  if (entries.length > 0) {
    upsertMany(entries)
    invalidate()  // 清除 system 级配置缓存
    // 通知热切换
    for (const [k, v] of entries) {
      notifyConfigChange(tenantId, k, v)
    }
  }
}
```

```typescript
type ModelInstance = any

// ── 对话模型 ──────────────────────────────────────────────────────────────────

/**
 * 获取对话模型实例
 * @param scenario     场景（决定默认温度和模型）
 * @param temperature  覆盖默认温度，null 则用场景默认值
 * @param modelName   覆盖默认模型名称，null 则用配置或场景默认
 * @param tenantId    租户 ID，null 则从当前请求上下文取
 */
export function createChatModel(
  scenario:    ModelScenario = 'default',
  temperature?: number,
  modelName?:  string,
  tenantId?:   string,
): ModelInstance {
  const effectiveTenantId = tenantId ?? getCurrentTenantId()
  const vendor   = getTenantVendor(effectiveTenantId)
  const adapter  = getAdapter(vendor)

  const effectiveTemp    = temperature ?? SCENARIO_TEMPERATURE[scenario]
  const effectiveModel   = modelName
    ?? getTenantChatModel(effectiveTenantId)
    ?? SCENARIO_DEFAULT_MODEL[scenario]

  const config: ChatModelConfig = {
    apiKey:    getTenantApiKey(effectiveTenantId),
    baseUrl:   getTenantBaseUrl(effectiveTenantId),
    modelName: effectiveModel,
    enableThinking: vendor === 'qwen',
  }

  const key = _chatCacheKey(effectiveTenantId, scenario, vendor, effectiveModel, effectiveTemp)
  if (!_chatModelCache.has(key)) {
    _chatModelCache.set(key, adapter.createChatModel(config, effectiveTemp, scenario))
    console.log(`[model/router] 创建对话模型: tenant=${effectiveTenantId}, scenario=${scenario}, vendor=${vendor}, model=${effectiveModel}, temp=${effectiveTemp}`)
  }
  return _chatModelCache.get(key)
```

## 六、后端配合事项

> `src/2model/router.ts` 依赖后端 JWT payload 中有 `tenantId` 字段。需要同步修改后端：

### 6.1 JWTUtils.java

```java
// JWT 生成时加入 tenantId 字段
payload.put("tenantId", user.getTenantId());   // 例如 "XMU_CS" 或 "FUDAN"
```

### 6.2 前置条件

在完成前端改动之前，**后端必须先完成 JWT 的 tenantId 注入**。否则：
- 后端 JWT 无 tenantId → 前端 `verifyJWT` 读到 `undefined` → 降级为 `'default'`
- 系统仍然正常运行，但所有请求都走到 `default` 租户（相当于单租户模式）
- 等后端部署好后，前端自动获得多租户能力（平滑降级）

## 九、向后兼容性说明

| 场景 | 行为 |
|------|------|
| 后端 JWT 无 `tenantId` 字段 | `verifyJWT` 中 `tenantId: (decoded['tenantId'] as string) \|\| 'default'`，降级为 default 租户 |
| `ai_tenant_config` 表无数据 | `getTenantConfig` 查不到则回退 `ai_config`（system 级），配置完全不变 |
| 旧数据库（无 tenant_id 列） | SQLite `ALTER TABLE ADD COLUMN` 自动给旧行填 DEFAULT `'default'` |
| `createChatModel()` 不带场景参数 | 默认 `scenario='default'`，行为与改动前完全一致 |
