二、面试可讲的项目亮点
亮点 1：LangGraph Agent 架构（ID-AIDemo）⭐⭐⭐
这是你项目最值钱的部分，面试官大概率会追问

我做了一个加分政策智能匹配系统，
核心用 LangGraph 做 Agent 编排。
用户上传证书后，系统会：
1. 先意图分类（咨询 / 申请 / 材料不足）
2. 根据意图走不同子图
   - 咨询子图：RAG 检索政策 → 生成回答
   - 申请子图：规则匹配 → 模板填充 → HITL 人工确认 → 提交
3. 引入 interrupt 机制，让用户在提交前确认
4. 用 SQLite 做 Checkpoint，支持会话恢复
可以深挖的点：

LangGraph 的 State 怎么设计的？各字段的 accumulate / replace 策略
interrupt 和 Command.resume 的机制
子图（Subgraph）怎么嵌入主图
为什么用 FAISS / 为什么不换成向量数据库
Embedding 模型选型（text-embedding-v3）、chunk 策略
亮点 2：多级审核流程（idbackend）⭐⭐
我负责了加分申请的多级审核流程：
- 学生提交申请 → 分配给多个评审
- 每个评审独立审核证明材料
- 审核状态机：待审核→已通过→已驳回→已撤销
- 记录完整的审核历史（reviewerIds、reviewRecords）
- 支持重新提交、撤回、批量审批
可以深挖的点：

状态机设计（各状态之间的流转条件）
为什么支持多评审人？怎么保证一致性？
审核通知怎么做的？（Redis pub/sub？）
亮点 3：RAG 知识库 + 文件解析（ID-AIDemo）⭐⭐
政策文件有 PDF、Word、Excel 多种格式，
我实现了统一的知识库构建：
- 用 pdf-parse / mammoth / xlsx 解析各类文件
- 文本分片后用 Embedding 模型向量化
- 存入 FAISS 向量库
- 检索时做相似度搜索，返回 Top-K 上下文
- 注入到 LLM 的 Prompt 中
亮点 4：RBAC 权限 + JWT 认证（idbackend）⭐
后端实现了完整的 RBAC 权限体系：
- 角色：super_admin、admin、reviewer、user
- 用注解 @RequireRole() 做方法级权限校验
- 权限信息 Redis 缓存 30 分钟
- JWT token 区分 accessToken（30min）和 refreshToken（7天）
- 登录加了图形验证码防暴力破解
亮点 5：文件存储 MinIO + 预览（idbackend）⭐
用户上传的证明材料：
- 存到 MinIO 对象存储（分布式）
- 生成预签名 URL，支持安全访问
- 支持 PDF、图片在线预览
- 文件元数据入库，区分 PUBLIC / AVATAR / PROOF 类型
