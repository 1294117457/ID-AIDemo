# 对话持久化与响应格式修复 — 测试文档

> 日期：2026-05-05
> 涉及工程：idagent、idfrontend、idfrontend-admin
> 修复方案：方案 B（统一修复响应格式 + 消息持久化）

---

## 一、修复内容概览

本次修复解决两个核心问题：

| # | 问题 | 根因 | 修复方案 |
|---|------|------|----------|
| 1 | 删除会话显示"删除失败"但 HTTP 200 | 前端 `res.code === 200` 判断在拦截器 reject 后失效 | 前端移除对 `res.code` 的冗余判断，依赖拦截器统一处理 |
| 2 | 点击历史会话消息为空 | 消息持久化路径正确但缺少调试日志，问题难以追踪 | idagent 增加 `[persist]` 日志 + 用户归属安全检查 |

## 三、测试用例

### 前置条件

- 启动 idbackend（端口如 8080）
- 启动 idagent（端口如 3001）
- 启动 idfrontend（端口如 5173）
- 使用学生账号登录

### 测试用例 1：会话列表加载

**目的**：验证会话列表正确显示，无响应格式解析错误

**步骤**：
1. 点击 AI 助手悬浮按钮，打开对话框
2. 发送一条消息"你好"
3. 等待 AI 回复完成
4. 再次点击悬浮按钮关闭
5. 重新点击悬浮按钮打开
6. 点击"历史会话"按钮（汉堡菜单图标）
7. 观察右侧是否显示会话列表（包含刚刚的对话）

**预期结果**：
- 会话列表正常显示
- 无 `加载会话列表失败` 的错误提示
- 控制台无 `{code: undefined}` 相关错误

**成功标志**：`✅ 通过` — 历史会话列表正常加载

---

### 测试用例 2：消息持久化（核心测试）

**目的**：验证对话消息正确保存到 idagent SQLite 数据库

**步骤**：
1. 登录后打开 AI 助手
2. 发送消息"请介绍一下厦门大学计算机系"
3. 等待 AI 回复完毕
4. **查看 idagent 控制台**，找到 `[persist]` 日志
5. 记录日志中的内容长度
6. 关闭对话框
7. 重新打开对话框
8. 点击"历史会话"
9. 选择刚才的会话
10. 观察消息列表

**预期结果**：
idagent 控制台应显示如下日志（格式：`[persist] ✓ 保存 xxx 消息，会话=sess_xxx，用户=xxx，内容长度=xxx`）：

```
[persist] ✓ 保存 user 消息，会话=sess_xxx，用户=1，内容长度=15
[persist] ✓ 保存 assistant 消息，会话=sess_xxx，用户=1，内容长度=128
```

重新打开后，历史消息正常显示，包含用户消息和 AI 回复。

**成功标志**：`✅ 通过` — 消息持久化成功，历史加载正常

## 五、问题排查

如果测试用例失败，按以下顺序排查：

### 5.1 删除会话失败

1. 检查 idagent 是否正常运行（`curl http://localhost:3001/health`）
2. 检查 idagent 数据库文件是否存在（`data/agent.db`）
3. 查看 idagent 控制台是否有 `deleteConversation` 相关日志
4. 打开浏览器开发者工具 → Network，查看 `DELETE /api/ai/conversation/sess_xxx` 的响应

### 5.2 消息为空

1. 查看 idagent 控制台是否有 `[persist]` 日志
2. 如果没有日志，说明 `streamAgent` 中的 `safeAppendMessage` 未被调用
3. 检查 idagent 是否正确收到 `x-user-id` 请求头
4. 检查 idagent 数据库文件权限

### 5.3 会话列表为空

1. 检查 idbackend 日志
2. 检查 idagent 数据库中是否有会话记录
3. 在浏览器控制台中手动调用 API 检查：

```javascript
// 在浏览器控制台执行
fetch('/api/ai/conversation/list', {
  headers: { Authorization: 'Bearer ' + localStorage.getItem('accessToken') }
}).then(r => r.json()).then(console.log)
```
