## 二、历史对话修复测试（Step 1）

**目标**：`last_message` 字段正确显示会话最后一条消息内容

### 2.1 测试步骤

1. **通过前端对话至少发送 3 条消息**（在 AI 悬浮按钮中发起对话）
2. **打开历史会话列表**（点击悬浮按钮 → 历史会话按钮）
3. **观察每条会话的预览文字**

### 2.2 预期结果

| 检查项 | 预期 |
|--------|------|
| 会话列表中每条记录的 `last_message` | 显示该会话最后一条用户消息或 AI 回复的完整内容（不再是 null 或"新对话"） |
| 消息数量 `message_count` | 正确反映该会话的消息总数 |
| 按日期分组 | 今天、昨天、更早日期正确分组 |

### 2.3 备选验证（直接调 API）

```bash
# 使用浏览器开发者工具或 Postman，在登录后调用：
GET http://localhost:8080/api/ai/conversation/list?limit=50&offset=0
Header: Authorization: Bearer <your_jwt_token>
```

检查返回 JSON 中每个会话的 `last_message` 字段是否非空。

### 2.4 根因确认

SQLite 中 `MAX(content)` 对空组返回 NULL，改用子查询后：
```sql
SELECT content FROM ai_message
WHERE session_id = c.session_id
ORDER BY created_at DESC LIMIT 1
```

| 检查项 | 操作 | 预期 |

| 右侧对话区 | 观察页面 | 有 AI 头像、欢迎消息 |

### 3.2 强制申请流程测试

1. 在"描述你的成果"中输入：
   ```
   我在2024年获得了全国大学生数学竞赛一等奖，证书编号CMSC2024001234
   ```
2. 点击"开始智能匹配"
3. 观察右侧对话区 AI 回复

**预期结果：**

| 检查项 | 预期 |
|--------|------|
| AI 回复内容 | 包含加分项匹配结果（如"全国大学生数学竞赛"匹配到某个加分模板） |
| 不出现咨询类回复 | 不应只回答"加分政策如下..."，而应进入申请引导流程 |
| 左侧出现匹配卡片 | 显示 1-3 个可申请的加分项及预计分值 |
| 后端日志 | idagent 控制台出现 `--apply:fetchPolicy` 和 `--apply:analyzeAndMatch` 日志（跳过 `--main:classifyNode` 的 LLM 调用） |

**验证跳过 classifyNode**：在 idagent 终端中，观察日志输出。如果传入了 `intent=apply`，应看到：
```
-main:classifyNode: forcedIntent=apply，跳过 LLM 分类
-apply:fetchPolicy
-apply:analyzeAndMatch
```
而不是：
```
-main:classifyNode: 意图=apply, 缺失=[], 材料=...
```

## 四、对话入口纯对话测试（Step 2-4）

**目标**：悬浮按钮的对话入口保持纯咨询，不主动引导申请

### 4.1 测试步骤

1. 点击悬浮按钮打开对话
2. 输入：`我想了解一下创新创业学分怎么算的`
3. 发送消息

### 4.2 预期结果

| 检查项 | 预期 |
|--------|------|
| AI 回复 | 解答创新创业学分政策，属于咨询类回复 |
| 不触发申请 | 不会出现"已为你匹配到以下加分项"等申请引导文案 |
| 不出现 interrupt | 不出现琥珀色中断提示框要求补充材料 |
| 正常对话延续 | 可以继续追问，系统保持在咨询模式 |

### 4.3 边界情况

尝试在对话中主动说"我要申请加分"，观察 AI 行为（由 LLM 分类决定 intent，不受 forcedIntent 影响）：

- 若 AI 识别为 `apply` intent 并引导申请 → **正常**（LLM 分类有效）
- 若 AI 仍保持咨询 → **正常**（LLM 认为信息不足以触发申请）

## 六、已知限制与后续优化

| 限制 | 说明 | 后续优化方向 |
|------|------|--------------|
| 证明材料文件 ID | 当前实现中 `proofValue` 填 0，需后端根据文件内容自动判定 | 在 `submitNode` 或 `AnalyzeService` 中加入文件内容分析逻辑 |
| 多个文件上传 | `applyStreamChat` 当前只传第一个文件 | 改为循环上传所有 `uploadedFiles`，所有 ID 合并到 `proofFileIds` |
| 申请会话与咨询会话未区分 | 共用同一套 session，当前无法在会话列表中区分 | 给申请会话的 `title` 加前缀（如"📋 申请-xxx"），或在数据库加 `type` 字段 |
| 申请中断恢复 | 页面刷新后申请流程中断，需重新开始 | 增加申请 session 持久化，前端存储 `apply_session_id`，刷新后自动恢复 |
