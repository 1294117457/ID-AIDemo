## Step 1: RAG 改为 Tool 调用

### 目标

将 `src/4node/rag.ts` 迁移到 `src/7rag/`，并包装成 LangChain Tool，使 Node 层通过 Tool 调用而非直接依赖。

### 预期文件变更

```
新增:
  src/7rag/index.ts        # 统一导出
  src/7rag/tools.ts        # 包装为 LangChain Tool

修改:
  src/4node/rag.ts         # 保留但标记 @deprecated，导出到 7rag
  src/4node/consultNodes.ts # import 路径改为从 7rag 导入
  src/4node/applyNodes.ts    # import 路径改为从 7rag 导入
```

### 操作步骤

#### 1.1 创建 `src/7rag/` 目录结构

```bash
mkdir -p src/7rag/adapters
```

#### 1.2 创建 `src/7rag/index.ts`

```typescript

// RAG 模块统一导出

```

#### 1.3 创建 `src/7rag/tools.ts`

```typescript
// src/7rag/tools.ts
// 将 RAG 能力包装为 LangChain Tool

import { Tool } from '@langchain/core/tools'

export const KnowledgeSearchTool = new Tool({
  name: 'knowledge_search',
  description: '当用户询问加分政策、申请流程、赛事等级认定等具体问题时使用此工具搜索知识库。输入应该是用户问题的核心关键词或完整问题。',
```

修改 `src/4node/consultNodes.ts`:

## Step 2: RAG 持久化向量库

### 目标

将 `MemoryVectorStore` 替换为持久化向量库，支持服务重启后数据不丢失。

### 方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| Chroma | 轻量、易部署、支持多语言 | 需要额外进程 | ⭐⭐⭐⭐ |
| Qdrant | 性能强、支持云原生 | 配置稍复杂 | ⭐⭐⭐⭐ |
| FAISS | 无服务器依赖 | 不支持实时更新 | ⭐⭐⭐ |
| SQLite-VSS | 零依赖、SQLite 生态 | 功能较新 | ⭐⭐⭐ |

### 推荐方案：SQLite-VSS（当前依赖最少）

SQLite-VSS 是 SQLite 的扩展，可以直接在现有 SQLite 基础上存储向量，无需额外服务。

### 操作步骤

#### 2.1 安装依赖

```bash
npm install @langchain/community better-sqlite3 sqlite-vss
npm install -D @types/better-sqlite3
```

#### 2.2 创建 `src/7rag/persistentStore.ts`

```typescript
// src/7rag/persistentStore.ts
// 基于 SQLite-VSS 的持久化向量存储

import { SqliteVSS } from 'sqlite-vss'
import { RecursiveCharacterTextSplitter } from '@langchain/textsplitters'
import { createEmbeddings } from '../2model/model.js'
import { getDb } from '../1config/config.js'

const splitter = new RecursiveCharacterTextSplitter({ chunkSize: 500, chunkOverlap: 100 })

let _store: SqliteVSS | null = null

export async function getVectorStore() {
  if (!_store) {
    const db = getDb()
    _store = new SqliteVSS(createEmbeddings(), { db, table: 'vector_store' })
  }
  return _store
}

// 其余 API (initKnowledge, searchKnowledge 等) 与 store.ts 类似
// 但使用 getVectorStore() 获取持久化存储
```

#### 2.3 更新 `src/7rag/index.ts`

```typescript
export { initKnowledge, searchKnowledge, ingestFile, removeSource, listSources, getStats } from './persistentStore.js'
export { createKnowledgeTools } from './tools.js'
```

### 备选方案：Chroma（如果需要更好的向量搜索能力）

```bash
npm install chromadb
```

```typescript
// src/7rag/chromaStore.ts
import { Chroma } from '@langchain/community/vectorstores/chroma'

let _store: Chroma | null = null

export async function getVectorStore() {
  if (!_store) {
    _store = await Chroma.fromExistingCollection(
      createEmbeddings(),
      { url: process.env.CHROMA_URL ?? 'http://localhost:8000' }
    )
  }
  return _store
}
```

```bash
# 3. 测试重启后数据是否保留
```

## Step 4: Node 持久化检查

### 目标

确认 LangGraph Checkpoint 持久化配置正确，确保对话状态可恢复。

### 当前实现

在 `src/5graph/graph.ts` 中：

```typescript
let _compiled: Awaited<ReturnType<typeof mainGraph.compile>> | null = null

export async function getCompiledGraph() {
  if (!_compiled) {
    const checkpointer = SqliteSaver.fromConnString(CHECKPOINT_PATH)
    _compiled = mainGraph.compile({ checkpointer })
  }
  return _compiled
}
```

### 检查清单

| 检查项 | 状态 | 说明 |
|--------|------|------|
| Checkpoint 数据库路径正确 | ✅ | `CHECKPOINT_PATH` 已定义 |
| `SqliteSaver` 可用 | ⚠️ | 需确认 `langgraph-checkpoint-sqlite` 已安装 |
| `sessionId` 正确传递 | ✅ | `config = { configurable: { thread_id: sessionId } }` |
| 首次对话创建 checkpoint | ✅ | LangGraph 自动处理 |

## Step 5: 对话压缩优化

### 目标

优化 `memory.ts` 中的对话压缩逻辑，减少 token 消耗。

### 当前实现分析

```typescript
// src/4node/memory.ts

const COMPRESS_THRESHOLD = 12   // 触发压缩的消息数
const KEEP_RECENT = 5           // 保留的最新消息数
const SUMMARY_TEMPERATURE = 0.1 // 摘要模型温度
```

### 优化方案

#### 5.1 添加 token 数量检查

除了消息数量，还应检查 token 总数：

```typescript
// 添加到 memory.ts

import { getTokenCount } from '../2model/tokenizer.js'  // 需要新增

export async function shouldCompressWithTokenCheck(
  messages: (HumanMessage | AIMessage)[],
  maxTokens: number = 3000
): Promise<boolean> {
  // 消息数检查
  if (!shouldCompress(messages.length)) return false
  
  // Token 数检查
  const totalTokens = await getTokenCount(messages)
  return totalTokens > maxTokens
}
```

#### 5.2 实现增量摘要（可选）

当前方案是全量压缩，可以改为增量：

```typescript
// 增量压缩：只压缩最早的 N 条消息，保留更多上下文

export async function incrementalCompress(
  messages: (HumanMessage | AIMessage)[],
  compressCount: number = 6  // 每次压缩 6 条
): Promise<(HumanMessage | AIMessage | SystemMessage)[]> {
  if (messages.length <= KEEP_RECENT + compressCount) {
    return messages
  }
  
  // 只压缩最早的 compressCount 条
  const oldPart = messages.slice(0, compressCount)
  const restPart = messages.slice(compressCount)
  
  const summary = await summarizeConversation(oldPart)
  
  return [
    new SystemMessage(`【对话摘要 ${new Date().toLocaleDateString()}】${summary}`),
    ...restPart
  ]
}
```

#### 5.3 添加压缩触发条件可配置

在 `src/1config/config.ts` 中添加：

```typescript
// 新增配置项
'compress_threshold': '12',
'compress_keep_recent': '5',
```

并在 `memory.ts` 中读取：

```typescript
import { getContextMaxMessages } from '../1config/config.js'

export function getCompressConfig() {
  return {
    threshold: parseInt(process.env.COMPRESS_THRESHOLD ?? '12'),
    keepRecent: parseInt(process.env.COMPRESS_KEEP_RECENT ?? '5'),
  }
}
```
